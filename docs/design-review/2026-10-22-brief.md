# Design review brief: ShelfSprite, 2026-10-22

You are a cloud session running a full design review of ShelfSprite with the impeccable skill. You
work unattended, from start to finish, and end by opening one pull request. Chase reads the PR; he
is not watching the session and cannot answer questions mid-run. Where this brief does not settle
something, choose the reading that keeps ShelfSprite's identity, note the choice in the PR, and
keep going.

## DECISIONS LOCKED (do not relitigate)

1. **The standard is ShelfSprite's own identity.** The approved design combines Ink & Paper's
   desktop rail and reading-first layout with Ember & Ivory's warm palette. Its authority is
   `docs/design-concepts/home-library/implementation.md`, `docs/design-concepts/home-library/README.md`
   and `docs/frontend.md`. Read all three before judging anything. The app is dark-only by design
   (`dark` is hardcoded on `<html>`); do not add a light theme.
2. **Chase's general house style does not apply wholesale.** It is for his status pages and
   dashboards. Only its portable rules (below) may be raised, each as an individual finding.
   Never move ShelfSprite toward the house style's look: no orange-alert system, no Bricolage-only
   type change, no departures-board layout, no IBM Plex swap.
3. **The PR contains fixes that keep character, plus proposals.** Apply fixes that keep identity:
   contrast, accessibility, broken or missing states, layout bugs at phone width, focus
   visibility, honouring `prefers-reduced-motion`. Anything that removes or flattens identity
   (signature motion, decorative elements, the reveal sequence's character, a brand colour move,
   the display face, the warm palette) is **not coded**. It goes in the PR as a one-line yes/no
   proposal.
4. **Front-end only.** Change files under `app/**` (pages, layouts, client components; never
   `app/api/**`), `components/**`, `app/globals.css`, `tailwind.config.ts` and `public/`. Do not
   touch `lib/server/**`, `app/api/**`, `proxy.ts`, `drizzle/**`, or anything in CLAUDE.md's
   load-bearing invariants. `lib/` client helpers only if a fix truly needs it.

## Rules for refining a site Chase already likes

These come from Chase's design-direction skill and are binding here:

- **Ask before removing identity.** A fix that removes or flattens what makes the site look like
  his goes to him as its own yes/no proposal, never as code. Agreeing to a fix list does not cover
  these.
- **Fix access, keep character.** Honour `prefers-reduced-motion` rather than removing motion for
  everyone. Step a colour darker or lighter for contrast rather than dropping it. Keep hover
  effects and add a visible focus state rather than deleting either.
- **A claimed brand beats a pattern warning.** The detector's and craft floor's warnings about
  gradient text or motion at rest do not outrank the approved design. The brief wins.
- **No email address on a public page.**

## The house style's portable rules (offer individually, never as a re-skin)

- **Step one accent by job for contrast.** Keep the hue, step it darker or lighter separately for
  fills, large marks and text until each passes WCAG (4.5:1 text, 3:1 large text and UI marks).
  Do not merge the steps back into one value.
- **Body text never below 13 px.** Labels sentence case; avoid uppercase letter-spaced
  micro-labels where they hurt reading. ShelfSprite's existing eyebrow labels such as "YOUR
  COLLECTION" are part of its identity: raise them as a proposal, do not change them.
- **Say the state in words first, then in numbers.** Empty, loading, error and calm states are
  designed as deliberately as the full state.
- **Fonts actually load.** Every face in use is loaded (here via `next/font`), with no fallback
  flash in a hero.
- **Tabular figures wherever numbers line up** (ratings, counts, columns).
- **Narrow layouts are designed, not scaled down.** A phone view rearranges; it is never a
  shrunken desktop.
- **No side stripes or edge bars** as decoration on rows, cards or callouts.
- **Spacing from one scale.** Flag one-off margins that break the rhythm.

## Setup

1. **impeccable.** Install the latest version:
   `claude plugin marketplace add pbakaus/impeccable` then
   `claude plugin install impeccable@impeccable`. A plugin installed mid-session does not
   register as a skill. Find `skills/impeccable/SKILL.md` under
   `~/.claude/plugins/cache/impeccable/impeccable/<version>/` and follow it directly, treating
   that directory as `CLAUDE_SKILL_DIR`. Use version 4.7.0 or newer and record the version in the
   PR. If the install fails, clone `https://github.com/pbakaus/impeccable` and use
   `plugin/skills/impeccable` (or wherever `SKILL.md` lives in that checkout). If the launcher's
   engine download fails, follow SKILL.md's "Launcher unavailable" path and say so in the PR.
2. **Database.** `service postgresql start`, then create a role and database, for example
   `review` / `review`. Run `npm ci`, then
   `DATABASE_URL=postgresql://review:review@127.0.0.1:5432/review npm run db:migrate`, then
   `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/demo-library.sql`. This loads a fictional
   19-book library with traits and an archetype under user `local`.
3. **App.** Run in local mode with no `.env` present and no Supabase variables:
   `ALLOW_LOCAL_AUTH=true DATABASE_URL=... npx next dev --port 3000`. Local mode marks `local` as
   admin. Check `GET /api/books` returns 19 books before you start.
4. **Covers and fonts.** Covers hotlink from `covers.openlibrary.org` and `books.google.com`, and
   `next/font/google` fetches from Google Fonts. If covers fail to load in the browser, the
   environment's network allowlist is missing them. Continue, judge cover-dependent layout from
   the fallback, and say so prominently at the top of the PR.

## The review

Use impeccable's `critique` on every surface, then `audit` for a11y, performance and responsive
checks. Use the mode impeccable assigns per surface: `/welcome` is Persuade; the app pages are
Operate; the profile reveal (`components/reveal/`) may be Experience. Capture every surface at
**1280 × 800 and 390 × 844**:

- `/welcome` (unauthenticated marketing; in local mode reach it directly), `/login`, `/setup`
- `/` (home), `/library` (each shelf tab, the filters open, a book detail modal, the enrichment
  correction modal), `/to-read`, `/discover`, `/swipe`
- `/profile` and the reveal sequence ("Replay my reveal")
- `/settings`, `/admin`, `/screen`, `/screen/library`, `/screen/profile`
- Empty, loading and error states wherever you can reach them honestly, for example by
  temporarily pointing at an empty database. Never fake a state with code you leave behind.

Rank findings by severity: blocking (broken, inaccessible, or unreadable), then major, then minor.
